# ComfyUI 本地实测：8G 显卡的显存与速度边界

> 在一台 **RTX 4060 Laptop（8G）** 上，把"本地出图到底能开多大、多快、代价是什么"量成一张可复现的表。
> 六组对照，**每组只改一个变量**；附脚本、工作流与口径。
>
> 本仓库只放**方法论与实测数据**，不含任何商业项目源码、素材或客户数据（见文末）。

---

## 为什么做这个

本地出图的瓶颈**通常不是"模型太大"，而是"你把画布开到多大"**。但社区里多是"能跑/不能跑"的定性说法，
很少有人给出**同一张卡、同一提示词、单变量**下的显存与耗时曲线。

这份实验就是补齐这一段：量峰值显存 + 墙钟耗时，并标出这台卡的**舒适区边界**。

---

## 环境

| 项 | 值 |
|---|---|
| GPU | NVIDIA RTX 4060 Laptop · **8188 MiB** |
| OS / Python | Windows 11 / 3.13 |
| ComfyUI | **0.28**（蒸馏 DiT、SDXL 类）· **0.37**（Qwen-Image-2.1，独立 venv） |
| 采样 | `nvidia-smi` **1 秒粒度**取最大值（热缓存，未逐组重启） |

---

## 方法（口径写在前面）

- 提示词 / 负向 / **种子 43** 全组固定
- **单变量**：每组只改一项（分辨率 or 模型 or 量化档）
- 峰值 = 生成过程中 `nvidia-smi` 采到的最大值
- 耗时 = 提交到落盘的墙钟时间（**含首次搬运模型**）
- 批量 1，无 hires、无 LoRA

---

## 结果

| 组 | 画布 | 像素面积 | 模型（步数） | 峰值显存 | 耗时 |
|---|---|---|---|---|---|
| ① | 512×768 | 39.3 万 | 蒸馏 DiT（6 步） | **5.9 GB** | **14 s** |
| ② | 896×1152 | 103.2 万 | 蒸馏 DiT（6 步） | **6.2 GB** | **37 s** |
| ③ | 1152×1536 | 176.9 万 | 蒸馏 DiT（6 步） | **6.0 GB** | **114 s** |
| ④ | 1152×1536 | 176.9 万 | SDXL 类（30 步） | **6.0 GB** | **72.8 s** |
| ⑤ | 896×1152 | 103.2 万 | SDXL 类（30 步） | **5.2 GB** | **61.9 s** |
| ⑥ | 1024×1024 | 104.9 万 | Qwen-Image-2.1 **GGUF Q4_K_M**（25 步） | **7.6~7.8 GB** | **772 s** |

> 卡总显存 8188 MiB ⇒ 第 ⑥ 组几乎顶满。

---

## 结论

**1. 峰值会被"夹平"，代价转移给时间。**
③ 比 ① 慢 **8.14×**，峰值只从 5.9 → 6.0 GB。装不下时 ComfyUI 不崩，改 offload / 分块 —— **税付在时间上**。

**2. 这台卡的舒适区 ≈ 100 万像素。**
①→② 面积 2.63×、时间 2.64× ⇒ **线性**；
②→③ 面积 1.71×、时间 **3.08×** ⇒ 多出约 **1.8 倍的"越界税"**。

**3. 步数少 ≠ 快 —— 蒸馏模型的悬崖更陡。**
舒适区内 6 步蒸馏（37 s）赢 30 步常规（61.9 s）；
越界后**被反超**（114 s vs 72.8 s）⇒ 选型看"实际尺寸落在谁家舒适区"，不是先砍步数。

**4. 权重文件小 ≠ 显存省（最反直觉的一条）。**
⑥ 主权重只有 **4.29 GB（全场最小）**，峰值却 **7.6~7.8 GB（全场最高）**。
两个原因：**文本编码器 5.88 GB 比主权重还大**；GGUF 的 4-bit 是"存着小、用着不小"（推理需反量化驻留）。
⇒ **显存要按「主干 + 文本编码器 + VAE + 激活」四份加总**，只看权重文件名一定算错。

**5. 质量与代价一起报。**
⑥ 画质明显最好，代价是 23× 时间、多 1.5 GB ⇒ 批量用 ② 档，关键镜才上 ⑥ 档。

---

## 显存不够时的三条路（按性价比）

| 序 | 手段 | 何时用 | 代价 |
|---|---|---|---|
| ① | **量化 / 换档位**（先核对总账，编码器可能比主权重还大） | 权重账本身超了 | 画质轻微下降 + 反量化开销 |
| ② | **offload / 分块下放**（文本编码器优先） | 峰值打到顶 | 速度与抖动 |
| ③ | **降规格**（先降帧数/分辨率，再换小模型） | 画质可让 | 画面信息量 |

## 复现

```bash
pip install -r requirements.txt

# ① 自动测峰值显存与耗时（0.25s 采样，比 1s 更准）
python lab_vram.py --url http://127.0.0.1:8188

# ② 把工作流导出成网页可导入的 JSON（按目标 ComfyUI 的 /object_info 现查参数顺序）
python lab_wf_export.py --url http://127.0.0.1:8188 --out workflows
```

`--only 03` 之类的子串可选跑单组；`--repeat 3` 取中位数。

> ⚠️ **两处坑，写在代码注释里也有**：
> 1. **权重缓存**：同模型第 2 次跑是"热缓存峰值"，要做冷启动对照就每组之间重启服务器。
> 2. **UI 格式的 `widgets_values` 是位置数组**，不同 ComfyUI 版本字段顺序会变 ——
>    所以 `lab_wf_export.py` 一律向 `/object_info/<节点>` 现查，不写死。

## 目录

```
lab_vram.py        峰值显存 / 耗时测量（后台线程采 nvidia-smi）
lab_wf_export.py   图定义 + API 格式 / UI 格式两种工作流导出
workflows/         导出结果（由 lab_wf_export.py 生成，.gitignore 里默认不提交）
```

改 `lab_wf_export.py` 顶部的 `MODELS` / `GRAPHS` 就能换成你本地的权重与参数组合。
